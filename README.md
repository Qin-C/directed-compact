# directed-compact

在 Claude Code 压缩上下文时,留下你点名要留的东西,压完再用脚本核对有没有丢。

## 问题

长对话到了一定长度要压缩。压缩是一次模型总结,默认由模型决定留什么:你的决定、被否掉的方案、某条警告的具体内容,都可能变成一句笼统的话,或者直接消失。下一轮模型照着摘要接着干,你要么重说一遍,要么没发现它已经忘了。

## 做法

1. **压之前,把要留的全文写进对话。** 按 7 类清单写一份检查点:用户的决定、未决事项、警告内容、被否选项和原因、当前身份和现场、最近的实测数字、在跑子代理的验收断言。
2. **压的时候,用带条数的指令点名。** `/compact` 后面写清每一类保留几条,要求写内容而不是标题。
3. **压完,用机器对账。** 脚本拿压缩摘要逐条比检查点,列出丢了或残了哪条,再到转录里找回来。

## 怎么用

不需要任何插件。最小用法是复制一行,改掉条数:

```text
/compact 逐字保留上文检查点:「本次必留」这一行原样;① 🔴 每一条原话拍板(含日期)共 N 条;② ⚠ 未决表每一行共 N 行;③ 🚨 每条警告的内容而不是标题,共 N 条;④ 🧠 被否掉的选项与为什么否共 N 个;⑤ 📌 的命令、数字、路径、标识符原样;⑥ 🛰 每个在跑子代理的验收断言;⑦ ▶️ 下一步原样;每一条都写出内容,不要用「同上」「略」代替。可丢:工具输出原文、中间尝试过程、已修好的报错堆栈。
```

这行指令依赖对话里已经有一份检查点。模板、7 类清单和没有检查点时的应急版本都在 [`template/compact-instructions.md`](template/compact-instructions.md)。

想让模型自己走完流程,把 `skills/directed-compact/` 复制到 `~/.claude/skills/`,然后说「写检查点」。模型写好检查点后会给你一整行 `/compact`,你粘贴执行,压完回一句话,它会对账并接着干。

压后对账(只用 Python 3 标准库):

```bash
python3 scripts/compare-summary.py <transcript.jsonl> <checkpoint.md>
python3 scripts/count-compactions.py <transcript.jsonl>
python3 tests/run.py   # 用虚构数据测这两个脚本
```

转录通常在 `~/.claude/projects/<项目目录名>/<会话 id>.jsonl`。

## 为什么压缩读不到文件

最早的设计是把检查点存成文件,让压缩去读。实测那一步一次都没有发生,压后连检查点的结构都没有。压缩这一步只有当前对话,没有文件系统。

所以检查点文件只是副本,用来给人回读和给脚本对账。让内容活下来的,是全文已经写进对话这件事。

## 实测数字

**带不带指令**

| 条件 | 结果 |
|---|---|
| 不带指令,单变量对照 | 42 条,丢 6 条,残 2 条 |
| 带指令,11 份 | 零丢失 |

**一次实际对账**

原话 9/9,未决 13/13,警告 16/16,在跑子代理 4/4。被否选项 9 条,机器核到 5 条,另外 4 条抽不出锚点,由人看过。

**压缩比例**(压前 → 压后 tokens)

| 压前 | 压后 | 比例 |
|---:|---:|---:|
| 652,401 | 12,160 | 1.9% |
| 423,509 | 14,600 | 3.4% |
| 867,895 | 24,322 | 2.8% |
| 572,518 | 18,117 | 3.2% |
| 576,998 | 12,522 | 2.2% |
| 527,713 | 22,244 | 4.2% |
| 527,091 | 24,371 | 4.6% |
| 559,679 | 27,702 | 4.9% |
| 519,686 | 25,982 | 5.0% |

比例小不代表压得好,要看对账结果。

**代价**:一段两周的统计里,写检查点加压后核对约占全部 token 用量的 7%,主要贵在来回次数。所以检查点要一条消息写完。

**这些数字的限定**

- 样本只来自一个人的使用,每组都小。上面两组对照来自不同时间段,不是同一批对话的平行实验,而且早于本仓库的对账脚本,当时不是用这个脚本核的。单独验证「全文进对话、不额外粘贴」的实验只有 1 份。
- 对账只比路径、数字、引文这些锚点。「在」只说明标识符活着,不说明意思没走样。
- 零丢失只说明压缩没丢,不说明检查点写对了,更不说明意思完整。
- 压缩会原样保留边界前最后几条消息。部分零丢失样本里的内容可能是被这一段保住的,这一点没有结论。
- 这些数字来自当时的版本和模型,会随版本变化。

## 兼容性

`compare-summary.py` 和 `count-compactions.py` 读的是 Claude Code 的转录文件,这不是公开接口,格式会变。

- 本机 `claude --version` 为 2.1.304。
- 记录版本为 2.1.317 的真实转录:配上对应的检查点,完整跑过对账和计数。
- 记录版本为 2.1.304 的真实转录:确认能解析摘要和压缩次数,没有配到对应的检查点,未做完整对账。
- 其他版本未验证。脚本读不到摘要时会以退出码 2 结束,不会报告「没有丢」。
