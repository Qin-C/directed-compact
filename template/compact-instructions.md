# 保留清单与指令模板

压缩是一次模型总结,只读得到当前对话。下面的清单决定检查点写什么,指令模板决定压缩时点名保什么。

## 7 类保留清单

| # | 类别 | 写什么 | 检查点小节 |
|---|---|---|---|
| 1 | 用户的决定 | 用户亲口的拍板、纠正、改变方向的话,逐字,带日期 | `## 🔴` |
| 2 | 未决事项 | 事项、建议、状态三列;等用户决定的写成待办,不要写成背景描述 | `## ⚠` |
| 3 | 警告和不该做的事 | 写内容和判据,不是标题。只剩一个词的警告比全丢更危险,因为它看起来还在 | `## 🚨` |
| 4 | 被否掉的选项 | 「不做 B,因为 C」一行一条。这一类最容易丢 | `## 🧠` |
| 5 | 当前身份和现场 | 会话名称、正在编辑的文件路径、协作方、关键命令 | `## 📌` |
| 6 | 最近一次实测 | 命令和输出里的数字原样,尤其是分支基点这类丢了就会写错的数 | `## 📌` |
| 7 | 在跑的子代理 | 派出时间、任务、期望产物、验收断言。丢了断言,结果回来时就没有判据 | `## 🛰` |

可以丢:工具输出原文、被否掉的中间尝试过程、已修好的报错堆栈、截图描述。

拿不准算不算重要,就保。漏保的代价是重建一轮,多保的代价只是几百 tokens。

## 检查点模板

小节标题开头的符号不要改,`scripts/compare-summary.py` 靠它们切段。

```markdown
> Checkpoint: <当前时间>
本次必留:原话 N 条 · 未决 N 行 · 警告 N 条 · 被否选项 N 个 · 在跑的子代理 N 个
## 🔴 原话拍板(逐字)
- 「用户的话」→ 已做 / 未做,日期
## ⚠ 未决
| 事项 | 建议 | 状态 |
|---|---|---|
## 🚨 警告
1. 一句内容 + 判据
## 🧠 被否掉的选项与为什么否
- 不做 B,因为 C
## 📌 现场
命令、数字、行号、路径、标识符原样
## ▶️ 下一步
1. 具体动作;没有活就写「无,等用户派」
## 🛰 在跑的子代理(有才写)
| 派出时间 | 任务 | 产物 | 断言 |
|---|---|---|---|
```

## 指令模板:有检查点时

把 N 换成检查点里的实际条数,`<>` 换成当前内容,整段放在一行里:

```text
/compact 逐字保留上文检查点:「本次必留」这一行原样;① 🔴 每一条原话拍板(含日期)共 N 条;② ⚠ 未决表每一行(事项/建议/状态)共 N 行;③ 🚨 每条警告的内容而不是标题,共 N 条;④ 🧠 被否掉的选项与为什么否共 N 个,<点名正在收敛的方案>;⑤ 📌 的命令、数字、行号、路径、标识符原样,不许概括;⑥ 🛰 每个在跑子代理的验收断言;⑦ ▶️ 下一步原样;每一条都写出内容,不要用「同上」「略」「共 N 条」代替。可丢:工具输出原文、被否掉的中间尝试过程、已修好的报错堆栈、截图描述。
```

条数和「内容不是标题」要一起用。只有条数,可能条数全对、内容却只剩标题。

指令里点名要保什么,不要让模型重抄上一次摘要。

## 指令模板:临时用,没有检查点时

```text
/compact 逐字保留:我做过的每一条决定(含日期);所有未决事项(事项/建议/状态);每条警告的内容而不是标题;被否掉的选项和原因;正在编辑的文件路径;最近一次测试的命令和数字原样;在跑的子代理及其验收条件;下一步。可丢:工具输出原文、中间尝试过程、已修好的报错堆栈。
```

这个版本内容没有先写进对话,也没有条数可以核对,只能算应急。README 里的数字不是用它测的。
